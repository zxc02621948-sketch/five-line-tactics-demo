# 五連戰線：遠端真人 Alpha

啟動 Node Server 後開啟 `http://房主IP:3000`，主畫面直接選擇模式：
- **連線對戰**：建立或加入房間，跟朋友遠端對戰。
- **單機測試**（`/local`）：對電腦或本機雙人。

**兩種模式使用同一份 `game_engine.js`，規則完全相同。** 單機不再有自己的引擎。

回合順序固定為 `P1 → P2 → 完整戰鬥結算`，先行者不交替。
交替先手只保留給開發測試，需在網址加上 `?turnOrder=alternating` 才會啟用，並會標示為非正式規則。

## 第一次啟動遠端 Alpha（Windows）
1. 安裝 [Node.js LTS](https://nodejs.org/)；安裝時維持預設選項。
2. 在專案資料夾雙擊 `start-alpha.bat`。
3. 第一次會安裝一個輕量的 `ws` WebSocket 套件，之後不會重複安裝。
4. 若 Windows 防火牆詢問，請允許 Node.js 使用「私人網路」。
5. 黑色視窗顯示 `Alpha Server: http://localhost:3000` 後，不要關閉它。
6. 房主用瀏覽器開啟 `http://localhost:3000`，按「建立房間」。
7. 把畫面上的 6 位房號告訴朋友；兩人都連線後自動開始。

也可以在終端執行：
```powershell
npm install
npm start
```

### 同 Wi-Fi 加入
1. 房主在 Windows 搜尋並開啟「命令提示字元」，輸入 `ipconfig`。
2. 找目前 Wi-Fi 的「IPv4 位址」，通常長得像 `192.168.1.25`。
3. 朋友在同一個 Wi-Fi 下開啟 `http://192.168.1.25:3000`（請換成房主實際 IP）。
4. 朋友輸入房主提供的 6 位房號並按「加入房間」。

### Tailscale 異地加入
1. 兩台電腦都安裝 Tailscale，並登入同一個 tailnet，確認彼此在線。
2. 房主啟動 `start-alpha.bat`。
3. 房主在 Tailscale 查看自己的 `100.x.x.x` 位址。
4. 朋友開啟 `http://100.x.x.x:3000`，再輸入房號加入。
5. 若無法連線，先確認黑色 Server 視窗仍開著，並檢查 Windows 防火牆是否允許 Node.js。

### 多人架構
- `server.js` 同時提供網頁、WebSocket、房間與短期重連。
- `game_engine.js` 是唯一正式遊戲狀態與規則結算來源。
- `alpha_client.js` 只送出部署／炮擊意圖並渲染伺服器回傳的私人狀態投影。
- 自己會收到完整手牌；對手只收到手牌數量。牌庫順序與未抽內容不會傳給 Client。
- 終局戰報寫入 `match_logs/日期_room-房號_match-id.json`。
- 房間在所有玩家斷線後保留約 30 分鐘；同一瀏覽器重新整理會使用本機 token 嘗試回到原座位。

## 目前規則（Alpha Core v1）

### 勝負與流程
- 9×9 棋盤，橫直斜任一方向五連獲勝。
- **每回合固定 `P1 部署 → P2 部署 → 完整戰鬥結算 → 檢查存活五連`。** 放下第五顆不會立刻獲勝，必須撐過該回合的戰鬥。
- 結算順序：產生主攻擊 → 護衛轉移與主傷害 → 移除主戰鬥陣亡 → ★★劍斬入與追擊 → 移除追擊陣亡 → ★★盾反震 → 移除反震陣亡。
- 只有單方在完整結算後保有五連才獲勝；雙方同輪五連會進入加賽，不再直接判平手。
- 加賽照常部署與戰鬥；3 輪緩衝後，每輪全場扣除各單位最大 HP 的 10%，直到只剩單方五連。
- 雙方連續 3 輪完全沒有攻擊關係時，視為消極對局，雙方棄賽並判雙敗。
- 只有一方在下一次行動補牌後仍無兵可部署時，另一方獲勝；雙方補給同時耗盡或棋盤已滿時判平手。

### 卡片
- 每人 25 張循環牌組：9 劍、9 盾、7 槍；手牌補到 5 張。
- 每回合必須部署 1 個單位；部署前可額外使用 1 次炮擊。
- 1 張＝★，**3 張同兵種＝★★**。**★★★ 已停用。**
- **每位玩家、每個兵種同時最多只能有 1 隻 ★★**（劍／盾／槍各自獨立）。該 ★★ 陣亡後解除限制。手牌足夠但已達上限時，仍可正常部署 ★。
- 單位陣亡後，綁定的卡進入 3 個「自己的回合」冷卻再洗回牌庫；★★ 陣亡時 3 張一起進冷卻。

### 兵種
- **劍** 120 HP / 24 攻：正交相鄰攻擊。**決鬥** — 只有單一目標時該次攻擊 +50%。剋槍、被盾剋。
- **盾** 160 HP / 20 攻：正交相鄰攻擊。**護衛** — 正交相鄰的非盾友軍受傷時，50% 改由盾承受（多盾平分這 50%）。剋劍、被槍剋。盾**沒有**自身減傷。
- **槍** 120 HP / 24 攻：正交方向射程 2 格。ATK 依**有敵人的攻擊方向數**平均分配（同方向多個敵人不會再稀釋）；第 2 格造成該方向 50%。剋盾、被劍剋。
- 克制倍率：盾→劍、劍→槍 +25%；槍→盾 +50%。

### ★★ 菁英（HP ×1.5、ATK ×1）
- **★★劍**（180 HP / 24 攻）**斬入**：以主攻擊親自造成致死傷害後，強制移入該敵人的死亡格，接著攻擊新位置正交相鄰中 HP 最低的敵人一次（100% base ATK，套克制、不套決鬥）。每次結算最多一次，追擊擊殺不會再次斬入；若 ★★劍在主戰鬥中已陣亡則不觸發。
- **★★盾**（240 HP / 不主動攻擊）**反震**：保留 50% 護衛；自己**實際被扣掉多少 HP，就對傷害來源造成等量反震**（不計 overkill）。即使因該次戰鬥陣亡，已記錄的承傷仍會反震。反震不會再觸發反震或護衛。
- **★★槍**（180 HP / 24 攻）**穿透**：可穿過第一格的單位攻擊第二格，射程仍為 2 格。第一格是敵人受該方向 100%、第二格敵人受 50%；第一格是友軍則友軍不受傷、第二格敵人仍受 50%。第二格不增加方向分母，克制前總輸出上限為 1.5× base ATK。

### 炮擊
- 每場 2 發、每回合最多 1 發，是部署前的額外行動；用完仍必須完成部署。
- 3×3 範圍敵我皆傷：中心 30、外圈各 12。

## 現行平衡報告

`balance_lab.js` 現在直接建立正式 `GameEngine` 對局，不再自行複製一套舊戰鬥規則。執行：

```powershell
npm run balance
```

輸出為 `simulation_report_alpha_core_v1.json`，並記錄當次 `game_engine.js` 的 SHA-256，方便確認報告與引擎版本相符。2026-08-25 的固定種子結果（每組每個座位 500 場）為：

- 均衡 AI 基準：P1 57.8%、P2 42.2%，平均 8.91 輪；非終局率 0%，卡片守恆率 100%。
- 使用炮擊對完全不用炮擊：炮擊方 70.6%。
- 積極合成 ★★ 對只部署 ★：合成方 71.7%。
- 槍偏好對盾偏好：槍偏好 59.5%、盾偏好 40.5%。

這些數字只比較簡單啟發式 AI 在同一版本下的差異，不代表真人最佳策略；但已能確認報告使用的是現行 ★★、加賽、消極判負與補給終局規則。

## 開發驗證

```powershell
npm test
npm install --no-save playwright-core
npm run test:browser
```

- `npm test`：核心規則、共用 UI、伺服器房間／重連／戰報測試。
- `npm run test:browser`：用兩個獨立瀏覽器環境實際建立房間、重連、部署、同步終局，並檢查隱藏手牌與終局摘要。
- `npm run test:all`：依序執行以上兩組；瀏覽器測試需要本機 Chrome／Edge，或用 `CHROME_PATH` 指定 Chromium。


## 視窗 / APP 模式
- 桌面版會固定在目前視窗高度內，棋盤自動縮放，右側資訊欄獨立捲動。
- 上方新增「全螢幕」按鈕。
- 已加入 PWA manifest / service worker 骨架。
- 若用本機 HTTP server 開啟（而不是直接 file:// 雙擊），Chrome / Edge 可將它安裝成獨立 APP 視窗。
- 手機寬度會自動切成直向版面。

### 最簡單的本機 APP 預覽方式
在資料夾內執行：
`python -m http.server 8000`
然後瀏覽器開 `http://localhost:8000/`

Steam 正式版之後可以再把同一套前端包進 Tauri / Electron；手機可走 PWA / Capacitor。現在先不引入這些框架，避免原型階段多一堆不必要的工程成本。

## 歷史紀錄

> 以下為早期版本的設計紀錄，**數值、勝負規則與沙盤工具皆已被上面的 Alpha Core v1 取代**，保留僅供追溯設計脈絡。

### v3 戰鬥節奏修正（歷史）
第一次實玩發現原數值過於致命，劍/槍大約兩次交戰就會死亡，導致棋盤只剩互殺、難以形成五連。

本版改為：
- 劍：25 HP / 5 攻
- 盾：32 HP / 4 攻
- 槍：24 HP / 5 攻
- 克制鏈：盾 → 劍 → 槍 → 盾
- 克制傷害由 +50% 改為 ×2
- 無克制時大致需要約 5 回合以上才容易擊殺
- （v3 當時）戰報與預覽標記「⚡克制 ×2」；目前 v6 已依現行個別克制倍率顯示。
- 炮擊因整體 HP 提高，暫調為中心 30 / 外圈 12

這仍然只是第一輪手感值，之後應以實玩結果繼續調整。


### v4 升階耐久修正（歷史）
實玩發現二星單位會被集火一回合蒸發。原因不是單純攻擊過高，而是舊版二星由 3 張卡合成，卻只有 1.75 倍生命，合成反而損失大量總耐久與佔格能力。

本版改為：
- ★：1× HP / 1× 攻
- ★★：3× HP / 1.8× 攻
- ★★★：5× HP / 2.8× 攻

設計目的：
- 高階兵用「少佔格」交換「高集中戰力」。
- 三張合一後，耐久不應比原本三張兵的總資源差太多。
- 攻擊不同比例放大，避免高階兵反過來造成秒殺 Meta。


### v5 沙盤推演（歷史）
使用簡化 AI，各跑 500 場比較同一套數值下的戰鬥頻率。

#### v4：每落一子，全場戰鬥
- 五連結束率：99.2%
- P1 勝率：65.0%
- P2 勝率：34.2%
- 平均落子：59.1
- 平均死亡：43.7
- 平均全場戰鬥結算：59.1 次

#### v5：雙方各落一子後，全場戰鬥一次
- 五連結束率：100.0%
- P1 勝率：47.2%
- P2 勝率：50.8%
- 平均落子：47.8
- 平均死亡：29.5
- 平均全場戰鬥結算：23.9 次

注意：AI 很簡單，數字只拿來比較規則方向，不代表正式平衡。


### v6：大整數＋兵種特色（歷史）
本版把核心數值改成較大的整數，目的是讓 50%、25%、多目標分攤等常用比例更容易得到整數結果，降低四捨五入造成的勝負爭議。

#### 基礎兵種
- 劍：120 HP / 24 攻；單一目標時 +50% 傷害。
- 盾：160 HP / 20 攻；自身減傷 25%；替十字相鄰友軍承擔 50% 傷害，多盾只平分這 50%。
- 槍：120 HP / 24 攻；直線 2 格，每方向第一個敵人；第 2 格只造成 50% 傷害。
- 克制：盾 → 劍、劍 → 槍為 +25%；槍 → 盾為 +50%。
- 炮擊：每場 2 發，每回合最多 1 發，可在正常部署前額外使用；中心 30 / 外圈 12，敵我皆傷。
- ★★：3× HP / 2× 攻；★★★：5× HP / 3× 攻。

#### 固定種子策略沙盤
當時的舊版沙盤每個指定對局配置跑 3,000 場：
- 無炮基準：平均 14.4 輪、11.5 個死亡。
- 積極炮擊對無炮（交換座位平均）：炮方勝率 64.0%，每場使用 1.98 發；配對反事實測試中有 44.2% 對局改變勝負結果。
- 槍偏好對盾偏好（交換座位平均）：槍方 45.9%、盾方 45.1%、平手 9.1%。
- 單一升階策略玩家平均每場部署 ★★劍 1.48、★★盾 1.16、★★槍 1.11。

舊 `simulation_report_v6.json` 因使用已停用的 ★★★ 與舊 ★★ 倍率，已從現行專案移除；目前請以 `simulation_report_alpha_core_v1.json` 為準。

#### 對局測試支援
- UI 會同時公開顯示 P1、P2 剩餘炮擊數。
- 每次炮擊記錄輪數、炮數、四／五連威脅是否被解除、直接擊殺、新空格、敵軍命中數與友軍命中。
- 終局摘要列出勝負、最終輪數、雙方炮擊使用輪數與剩餘炮數，並同步輸出到瀏覽器主控台。
- 當時另曾統計 ★★單位的存活輪數、實際承傷、有效輸出與最終五連參與率；該資料只屬於 v6 舊規則，不得套用到 Alpha Core v1。
